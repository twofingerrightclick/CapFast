# Language-switch timeout recovery — earlier implementation

**Superseded validation:** The implementation and checks below describe the earlier timeout-skipping path. The user correctly rejected its lost captions and stuck dominant-language indicator. Current work replaces the production detection/translation chain and removes queue-age expiry; see [the video transition validation](swahili-only-validation.md). Earlier unit-test and reviewer passes do not establish live acceptance.

The reported diagnostics showed a Google text translation timeout stopping and restarting the entire caption session after a language change. A deterministic regression drives the real translator and source pipeline through English, five seconds of silence, and Swahili. The fake HTTP transport times out on the first Swahili request. Before the fix, the regression fails because the pipeline raises its session-failure event. After the fix, it emits a diagnostic and delivers the following Swahili caption without recreating the pipeline. Both queued source chunks and received finals are covered.

Translation timeouts, exhausted transient HTTP retries, and network interruptions now carry an explicit recoverable translation flag. The source pipeline skips the affected segment and releases its ordering barrier, allowing later speech to proceed. Authentication, quota, configuration, and other terminal errors retain their existing failure handling. Temporary errors do not cancel capture or reset language assignment.

Language classification has a four-second deadline and each translation request has a five-second deadline, including retries (previously twenty seconds each). The detector now allows 4,096 output tokens because [Gemini counts internal thinking against the output cap](https://ai.google.dev/gemini-api/docs/thinking); the previous 64-token cap caused observed `MAX_TOKENS` language-check failures. A nonterminal language-check failure uses automatic source translation for that chunk and retries classification after a two-second cooldown. Authentication, quota, and configuration errors remain terminal. A blocked or prohibited-content response withholds that segment without retrying it or stopping later captions; blocked language checks never pass the same text to translation. Accepted source has an eight-second age budget covering classification, queue wait, and translation; expired chunks emit a diagnostic and release their ordering barrier. At most two language checks begin ahead of the ordered translation queue, while assignment and caption output still follow source order. Independent stalled-HTTP checks exercise the request cancellation deadlines. These limits do not bound recognition latency or connection setup. A skipped segment is not replayed automatically. A sustained source backlog still pauses capture at the configured queue limit so accepted source is not silently dropped.

Validation: `dotnet run --no-restore --project tests/CapFast.Checks -p:UseSharedCompilation=false`. This is deterministic transport validation, not a live microphone/provider latency measurement.

## Alternating-speaker commentary

A second screenshot showed translation-task commentary, including the private `previousSource` and `sourceToTranslate` field names, on the audience surface. Replaying that response through the real translator and pipeline reproduced the leak. The content guard now rejects these markers anywhere in a response; rejection is recoverable so the following caption can proceed. Ordinary discussion of English, Swahili, or translation is not blocked by broad keyword matching.

The translation prompt now treats detected source language as a hint, handles mixed-language fragments and words already in the target language, and explicitly prohibits explanations of language mismatches. The revised prompt was exercised with the supplied alternating-speaker fixture against the live provider; see validation below.

A separate regression reproduced a cached-language issue: an English interim followed by a wholly revised Swahili final kept its English classification. The resolver now rechecks a final once if the prefix used for detection no longer matches. Production translation identifies each emitted source chunk after stable interim or final segmentation, so an English sentence followed by a Swahili sentence in one cumulative transcript can route each sentence to its proper output pair. Explicit hints and provider metadata retain priority. This does not provide speaker diarization or guarantee detection of a switch inside one emitted chunk.

The resolver also rechecks a revised interim when its detected prefix changes. Returning to a language after another speaker now starts fresh translation context, so older source text cannot influence the new request. These changes cover alternating English–Swahili–English speech within one audio block; a late suffix from a retired audio block still uses its original block context.

Checks cover screenshot commentary rejection, continued captions after rejection, ordinary speech false positives, and revised-final language detection. The complete checks suite passes.


## Independent review and live validation

A Sol implementation agent and two independent default-model reviewers handled this fix. The requested Terra model was unavailable. Review found and corrected two additional defects: serial queue wait was outside the HTTP deadline, and a cumulative transcript could contain both speakers while retaining the opening language. Follow-up review verified bounded two-way language detection, source-ordered assignment/context/translation, persistent utterance hints, queue age cancellation, and provider refusal handling. Both final reviewers reported no unresolved actionable findings.

The first 83-second real-provider replay produced 19 caption pairs without a session failure or leaked commentary, but skipped two delayed segments. A second instrumented replay exposed a provider `PROHIBITED_CONTENT` response stopping capture, and detection consuming the remaining queue age budget. Provider-blocked segments now remain withheld without retries or automatic-translation fallback; later speech continues. Detection can run two requests ahead while assignment and translation remain ordered.

The diagnostic harness and reports are in `artifacts/debug-language-switch-replay/`. It paces the supplied 83-second English/Swahili playlist, including its seven-second silence, through the production session and real Google APIs. Digital silence is labeled quiet and other frames speech, bypassing native microphone classification. It records test-fixture caption text, stage timings, and safe diagnostics locally; it does not log credentials or raw provider responses. These are fixture runs, not a microphone or full-seminar accuracy guarantee.

The parent independently ran the complete checks suite, built both evaluation tools, published the macOS app, and verified stable app/helper signatures. The app opens paused; a caption-rendering preview displayed both columns successfully. Settings guidance now describes segment-level detection and automatic recovery. No tracked user changes were discarded.

Final approved replay (`final-replay.json`): 19 caption pairs, two expected connections across the seven-second silence, no session failure, no `MAX_TOKENS`, no internal-field commentary, and no queue-age expirations. One Google translation request reached its five-second timeout at 44.57s; that segment was skipped diagnostically and capture continued. Swahili speech resumed at 45s and its first translated pair arrived at 51.68s (6.68s later, including speech qualification/recognition). The measured repeat still demonstrates variable provider latency and occasional skipped captions, so this is not a claim of lossless or instantaneous translation. One short source fragment was classified as `sn` and another as `auto`; both used English/French outputs. This fixture validation does not establish perfect language identification or translation accuracy.
